## 0. 第1版からの変更点

定義が「マイナスから価値を取り出す」から「**今すぐ解消できない制約の下での行動選択**」に変わったことで、
脅威度の順位が大きく入れ替わった。

| 概念 | 第1版 | 第2版 | 理由 |
|---|---|---|---|
| 安全実務の「暫定措置」 | 未登録 | **1位** | 「今すぐ直せない前提での対処」という構造が完全に一致 |
| First/Second-order problem solving | 未登録 | **2位** | この思想の失敗モードを実証的に記述している |
| Bricolage | 未登録 | **3位** | 資源制約下で手元のもので間に合わせる。前提条件が一致 |
| Effectuation / レモネード原則 | 1位 | 6位 | 「予期せぬ事態の活用」であって「制約の持続」が前提ではない |
| TRIZ 原理22 | 2位 | 8位 | 技術的矛盾の解消手段。制約持続の前提がない |
| Reframing | 3位 | ティア3 | 意味づけの変更。新定義は行動選択なので距離が開いた |
| Service Recovery | 5位 | ティア3 | 失敗後の回復であり、制約の持続とは別 |

**この入れ替わり自体が、定義修正の効果を示している。**【推】
心理・意味づけ系の概念から距離が開き、実務・組織運営系の概念に近づいた。これは狙い通りだが、
**新しく近づいた相手（暫定措置・first-order problem solving・bricolage）の方が構造的に近い**ため、独自性の検証はむしろ難しくなった。

## 1. ティア1：最優先（ここが黒なら概念を組み替える）

### 1. 安全・保全実務の「暫定措置 / 応急対策 / 恒久対策」【最優先】
- なぜ脅威か: 【事】残留リスクが残る場合、**①作業者への周知 ②暫定措置の実施 ③恒久対策を計画に反映**、という手順が既に標準化されている。新定義の要素①③④とほぼ一致する。
- 確認すべき点:
  - 暫定措置の選定基準に「副次的価値」の観点はあるか（**無ければ、そこが独自性の隙間**）
  - 対象は設備・作業に限られるか、接客・営業のような対人場面を含むか
  - 誰が判断主体か（組織か、現場の個人か）— **個人の秒単位の判断を扱っていなければ、そこが隙間**
- 出典の起点: https://anzeninfo.mhlw.go.jp/yougo/yougo01_1.html , https://www.mhlw.go.jp/bunya/roudoukijun/anzeneisei14/dl/130316.pdf
- 隣接: 設備保全の「暫定処置／恒久処置」、品質管理の「応急処置・是正処置・予防処置」（ISO 9001 の用語と対応を確認）

### 2. First-order / Second-order problem solving（Tucker & Edmondson）【最優先】
- なぜ最重要か: 脅威であると同時に、**この思想の失敗モードの実証的記述**である。
- 【事】看護師はシステム不具合の約93%を first-order（その場しのぎ）で処理し、問題が組織に上がらず学習が起きない。論文タイトルは "When Problem Solving Prevents Organizational Learning"。
- 確認すべき点:
  - second-order へ移行させる条件として何が特定されているか（**これはそのまま本研究の要素④の設計材料になる**）
  - 心理的安全性・報告コストとの関係
  - 「上手にしのげる人ほど組織が学習しない」という逆説の扱い
- 出典の起点: https://www.researchgate.net/publication/200552323_When_Problem_Solving_Prevents_Organizational_Learning , https://www.jenonline.org/article/S0099-1767(18)30344-1/fulltext

### 3. Bricolage（Lévi-Strauss / Baker & Nelson 2005）
- 【事】Baker & Nelson (2005) は資源制約下の29社を調査し、「手元にあるものでやりくりする（making do with what is at hand）」で説明した。他社が捨てた・無視した物理的・社会的・制度的な資源を再結合する。「**支配的な資源環境の定義が課す限界を、そのままには受け入れない**」点が中心的な貢献とされる。
- なぜ脅威か: 「制約を前提として、手持ちで一手を作る」という構造が一致。
- 確認すべき点: 対象は企業・組織レベルか個人の行動か。時間スケール（戦略的か、秒単位か）。副次価値の同時獲得という選択基準はあるか。
- 出典: https://journals.sagepub.com/doi/10.2189/asqu.2005.50.3.329

### 4. Satisficing / 制約下の意思決定（H. Simon, bounded rationality）【未確認】
- なぜ脅威か: 「最適解が取れない条件で、十分な解を選ぶ」という定式化が既にある。
- 確認すべき点: 行動まで要求するか。現場の対人場面に適用された研究があるか。

### 5. Organizational improvisation / Adaptive performance
- なぜ脅威か: 計画外の状況で即座に行動を組み立てる研究群。秒〜分単位を扱う点で最も時間軸が近い。
- 確認すべき点: 前提が「計画が使えない」なのか「制約が解消できない」なのか。この違いが残れば独自性になる。

### 6. Effectuation / Lemonade Principle（Sarasvathy）
- 第1版で1位だったが降格。「予期せぬ事態を資源として活用する」は近いが、**制約が持続すること**を前提にしていない。
- 確認すべき点: レモネード原則の正確な記述。適用主体が起業家に限定されるか。

## 2. ティア2：差分を明確にすれば共存できる

| 概念 | 想定される差分の方向【推】 | 確認事項 |
|---|---|---|
| KAIZEN / トヨタ生産方式 | 改善（B）側の代表。**応急処置と恒久対策を分けて扱う実務**がある点は要確認 | 「異常で止める」思想と、本研究の「止めずに一手」は矛盾しないか。**ここは正面から扱う必要がある** |
| KYT（危険予知訓練） | 事前に危険を予知する訓練。本研究は**危険が既にあって消せない**状態を扱う | 「KYTの接客版では？」への回答を用意する |
| Resourcefulness | 個人特性・能力の話。本研究は判断の型 | 特性か技能か行動かの整理 |
| Opportunity recognition | 機会の発見。本研究は制約下の行動選択 | 「機会」と「副次価値」の関係 |
| Constraints-based thinking / 制約が創造性を高める研究 | 制約が発想を促すという実証群。**援護になる可能性が高い** | 制約が創造性を高める条件（強すぎる制約は逆効果という知見の有無） |
| Resilience | 回復する力。本研究は制約が残ったままの行動 | 層が違うことを明示できるか |
| TRIZ 原理22 | 有害を有益に変える発明原理 | 技術領域限定か |
| Design Thinking / JTBD | プロジェクト単位・設計行為。時間軸が違う | 現場の即応を扱っていないことの確認 |
| Service Recovery | 失敗後の回復。**再購買への効果は実証が弱い**（確認済） | 「制約」ではなく「失敗」が対象である点の確認 |
| Stoicism / The Obstacle Is the Way | 態度・徳。行動の型ではない | 「コントロールできることに集中する」との差分。**実はかなり近い**ので要注意 |

## 3. ティア3：反対側から殴る（この思想を否定しに来る側）

| 概念 | 何を検証するか |
|---|---|
| **Workaround 批判（医療安全・情報システム）** | 現場の迂回策が、問題を不可視化し、恒久対策を遅らせるという実証。本研究への最強の反論 |
| **Normalization of deviance（D. Vaughan）** | 【事】悪い結果が出ないまま逸脱が繰り返されると、それが組織の標準になる。暫定措置の常態化を説明する。https://en.wikipedia.org/wiki/Normalization_of_deviance |
| 感情労働（Hochschild） | 従業員に感情管理と工夫を要求することの負荷 |
| カスタマーハラスメント対策 | 「クレームを機会にせよ」が従業員保護と矛盾しないか |
| 自己責任論／構造的問題の個人化 | 経営が「工夫しろ」で済ませる装置にならないか |
| ポジティブシンキング批判（Ehrenreich ほか） | C との境界を外から検証 |

## 4. 各概念で埋める共通テンプレート

```
### 概念名（原語 / 提唱者 / 年 / 主要文献 / URL）
0. 一次資料に当たったか（はい / 二次資料のみ）
1. 定義（原典の言葉で。引用は「」）
2. 主な目的
3. 思考プロセス（手順があれば手順の形で）
4. 中心質問への回答
   (1) 問題そのものを解決する思想か
   (2) 制約を前提に動く思想か
   (3) 予期せぬ出来事を利用する思想か
   (4) 資源不足の中で工夫する思想か
   (5) 意味づけを変える思想か
   (6) 具体的な行動まで要求するか
   (7) 現場の数秒単位の判断に使えるか
   (8) 記録・報告を要求するか  ← 追加項目
5. 本研究と同じ部分
6. 本研究にしか残らない部分
7. 侵食可能性: 高 / 中 / 低 ＋ 理由
8. 借りられる部分（部品として使える点）
9. この概念から受ける最も鋭い批判
```

※ 4-(8) と 8・9 は本人のテンプレに無いが追加した。
(8) は要素④の独自性を判定する軸、8 は独自性が無かった場合の再利用、9 は 06_MISUSE_AND_BOUNDARIES.md の材料。

## 5. Phase 1 の停止条件

- **ティア1の1（暫定措置）が、副次価値の選択基準まで含んでいた** → ほぼ言い換え。定義を案2から案1へ後退させるか、領域特化（対人・秒単位）に賭けるかを判断する。
- **ティア1で「侵食可能性: 高」が3つ以上** → 既存概念の組み合わせと判定。組み合わせ方の新規性のみで勝負できるかを検討する。
- **要素④（記録・報告とセット）を既に要求している概念が見つかった** → 最有力の独自性が消える。その場合、残るのは領域特化のみ。
- 「高」が0〜1 → 調査不足を疑う。二次資料だけで判断していないか確認する。
