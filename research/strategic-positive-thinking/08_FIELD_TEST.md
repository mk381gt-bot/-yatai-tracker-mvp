## なぜ前倒ししたか

当初は「フレームワーク確定後に30日試す」計画だった。これを変更した。

理由（発見4）: **常態化した制約は、エピソードとして想起されない。**
工場の事例を2回求めて2回とも一般論（「上層の判断」「全部金額の問題」）で返ってきた。
一方、昨日の非日常の出来事（カーペット）は細部まで想起された。
毎日ある制約は「状態」として記憶され、個別の出来事に分解できない。

→ 思い出す方式では、30例が非日常の出来事に構造的に偏り、**工場の事例が1件も入らない**。
→ 想起をやめ、**その日に書く**方式へ切り替える。

## 記録フォーマット（1分で書く。重くしない）

出勤した日に、**1件だけ**。長く書かない。思い出せる程度のメモで十分。

```
## MM/DD（場所: 工場 / 現場 / その他）
- 普段なら:
- できなかった:
- やった:
- 自分だけ気づいてた? → 伝えた / 伝えてない / 全員知ってた
```

### 各項目の意図

| 項目 | 何を検証しているか |
|---|---|
| **普段なら** | 発見2の検証。「本来やるはずだった手」が毎回存在するか。存在すれば、発動の引き金は「標準手順が封じられたこと」で確定する |
| **できなかった** | 第1層（発動条件）の実態。制約の種類が偏るか（権限／金銭／時間…） |
| **やった** | 第2層。一手が出たか。**出なかった日は「なし」と書く**（＝C。これも必要なデータ） |
| **自分だけ気づいてた?／伝えた?** | 発見3の検証。第4層が実際に働くのは、気づいた人が自分だけのとき。伝えたか伝えなかったかで、後に何が起きたかが変わる |

### 書くときのルール
- **何も起きなかった日は「なし」と1行だけ書く。** 発動しない日の頻度そのものがデータになる（＝この思考法が実際に必要になる頻度）
- **何もできなかった日も書く。** それがC。空振りも逆効果も書く
- うまくいった理由は書かない。起きたことだけ
- 後から「これは価値があった」と気づいたものは、**その日ではなく気づいた日に追記**する（F の検出）
