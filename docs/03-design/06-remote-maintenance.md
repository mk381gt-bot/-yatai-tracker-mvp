# 3-6 遠隔点検の仕組みとセキュリティ

## 基本方針

1. **顧客側でポートを開けない**（外向き接続のみ）
2. **中身を見ない点検**を原則にする（稼働情報・ハッシュ値・件数だけを見る）
3. **顧客が止められる**（保守時だけ接続を許可するスイッチ）
4. **誰が・いつ・何をしたか**を記録し、顧客に開示する
5. 顧客同士は絶対につながらない

## 構成

| 役割 | 方式 | 中身 |
|---|---|---|
| ① 監視（常時） | AIサーバー → 当社監視サービスへ **送信のみ**（プッシュ型） | 稼働中か、CPU/GPU温度、ディスク残量、バックアップ成否、エラー件数。**質問・回答・文書の中身は送らない** |
| ② 点検・作業（必要時） | メッシュVPN（WireGuardベース）で当社点検端末からSSH接続 | 更新作業・設定変更・ログ確認 |
| ③ 画面操作（例外時） | 顧客PCの画面共有（顧客がその都度承認） | 顧客担当者との画面を見ながらの相談 |

## 遠隔接続（②）の候補比較

| 候補 | ライセンス | 商用利用 | 更新状況 | 利用者数 | 注意点 |
|---|---|---|---|---|---|
| **Tailscale** | クライアント：BSD-3／制御サーバー：独自SaaS | ○（有料プランあり） | 非常に活発 | 多い（企業利用多数）［推定］ | 制御サーバーが外部SaaS（米国）。ただし通信内容は端末間で暗号化され中継されない設計。アクセス制御（ACL）、MFA、端末承認、Tailnet Lock（署名済み端末のみ参加）あり |
| Headscale | BSD-3 | ○ | 活発 | 中［推定］ | Tailscale互換の制御サーバーを自前で運用。SaaS依存がなくなるが、制御サーバーの保守と安全確保が当社の責任に |
| NetBird | クライアント BSD-3／サーバー AGPL-3.0［要確認］ | ○ | 活発 | 中［推定］ | 自前運用も可。欧州企業 |
| WireGuard（素の設定） | GPL-2.0 等 | ○ | 安定 | 多い | 最もシンプルだが、鍵配布・アクセス制御を手作業で管理 |
| RustDesk（画面共有③用） | AGPL-3.0 | ○（自前サーバー可） | 活発 | 多い［推定］ | 画面共有用。自前中継サーバーで外部依存を減らせる |

## 監視（①）の候補

| 候補 | ライセンス | 注意点 |
|---|---|---|
| **Healthchecks（自前運用可）／死活通知** | BSD-3 | 「定時に通知が来なければ異常」というプッシュ型。顧客側の受信ポート不要 |
| Uptime Kuma | MIT | 画面が分かりやすい。プッシュ型監視にも対応 |
| Prometheus＋node_exporter＋Grafana | Apache-2.0（Grafana は AGPL-3.0） | 本格的だが一人運用には重い |

## 推奨

**仮決め：** 遠隔接続は **Tailscale**（当社の1つのネットワーク内で、顧客ごとにタグとACLで分離）。監視は **Healthchecks＋Uptime Kuma のプッシュ型**。
- 理由：一人で多数の顧客を安全に管理するには、MFA・端末承認・ACL・ログが最初から揃ったものが確実。自前の制御サーバーを守る負担を避ける。
- 安全策：
  - ACLで「当社点検端末 → 各顧客AIサーバーのSSHのみ」を許可。顧客AIサーバー同士、顧客 → 当社は禁止。
  - Tailnet Lock を有効化（当社が署名した端末しか参加できない）。
  - SSHは鍵認証のみ・パスワード禁止・root直接ログイン禁止。
  - 顧客側に「保守接続スイッチ」（VPNサービスの停止／起動手順、または通常時は停止しておき、点検日だけ顧客が起動）を用意。
  - 点検端末は専用PC（他の用途に使わない、ディスク暗号化、OS自動更新）。
  - 接続ログ（Tailscaleの監査ログ＋サーバー側のSSHログ）を月次報告に添付。
- 別案①：**Headscale を当社で運用**（外部SaaS依存をなくしたい顧客向け。当社の運用負担と、制御サーバーが侵害された場合の影響が増える）。
- 別案②：**顧客ごとに別の Tailscale ネットワーク**（分離は最も強いが、アカウント管理が顧客数分に増える）。

**仮決め：** 標準は「常時接続」、顧客の希望で「点検日のみ接続」に切替可能。
- 理由：障害時の初動を速くするため。
- 別案：標準を「点検日のみ接続」（安全側。ただし障害時は顧客に起動してもらう手間がかかる）。

## 当社側のセキュリティ（踏み台にならないために）

| 項目 | 対策 |
|---|---|
| 点検端末 | 専用機・ディスク暗号化・画面ロック・OS自動更新・ウイルス対策 |
| アカウント | 全サービスでMFA（ハードウェアキー推奨）。パスワード管理ツール |
| 認証情報 | 顧客ごとに別の鍵。漏えい時は顧客単位で失効 |
| 記録 | 作業ごとに「日時・顧客・作業内容・結果」を記録（点検記録に転記） |
| 事故時 | 当社が侵害された疑い → 全顧客のVPN接続を即時停止 → 顧客へ連絡 → 保険会社に連絡 |
