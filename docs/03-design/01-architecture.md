## 使い分けのルール（データの機密区分）

| 区分 | 例 | 使えるAI | 理由 |
|---|---|---|---|
| **L3 機密** | 取引先の図面・仕様書、見積原価、入札情報、個人情報（社員・顧客）、品質不具合の詳細 | **ローカルのみ** | 契約・法律で社外提供が制限される／漏れたら取り返しがつかない |
| **L2 社内** | 社内手順書、議事録（個人名なし）、一般的な技術資料 | ローカル優先。必要時は法人契約のクラウドAI（学習利用なし）も可 | 漏えい時の影響は中程度 |
| **L1 公開** | 公開情報の調査、一般的な文章作成、プログラム作成、法令の一般的な解説 | クラウドAI推奨 | 高度な推論が必要で、機密性がない |

### 実装方法（段階的）

1. **画面で分ける**：Open WebUI 上で、ローカルモデルは全員に表示、クラウドモデルは「許可グループ」にだけ表示。モデル名に【社外送信】と明記。
2. **ルールで分ける**：A4 1枚の「AI利用ルール」（L3の例を業種ごとに具体的に書く）。
3. **ログで確かめる**：月次点検でクラウドAIへの送信内容を抜き取り確認（[04-maintenance](../04-maintenance/01-menu.md)）。
4. （将来）**自動で止める**：個人情報・図番などのパターンを検出してクラウド送信を止める仕組み。

**仮決め：** 最初は 1〜3（画面・ルール・ログ）で運用し、自動検出（4）は後回し。
- 理由：日本語の個人情報自動検出は誤検出・見逃しが多く［推定］、作り込みの工数が大きい。中小ではまず「見える化と教育」が効く。
- 別案：導入時から、図番・品番・氏名などの正規表現による送信ブロックを入れる（安心感は高いが、誤ブロックで現場が使わなくなる恐れ）。

**仮決め：** クラウドAIは顧客が直接契約（当社は設定のみ）。
- 理由：クラウド側の規約・障害の責任を当社が抱えない。費用も顧客の実費。
- 別案：当社がAPI契約をまとめて従量課金で再販（利益は出るが、データ処理の委託関係が複雑になる）。

## 標準で提供する「定型業務」テンプレート（初期5本）

| テンプレート | 区分 | 入力 → 出力 |
|---|---|---|
| 日報・作業報告の要約 | L3（ローカル） | 箇条書きメモ → 定型の日報文 |
| 過去の不具合・事故事例の検索 | L3 | 症状・状況 → 類似事例と当時の対策（参照文書つき） |
| 社内規程・手順書Q&A | L2 | 質問 → 回答＋該当条文 |
| 報告書・是正処置書の下書き | L3 | 事実メモ → 書式に沿った下書き |
| メール・案内文の文案 | L1/L2 | 要点 → 丁寧な文面 |
