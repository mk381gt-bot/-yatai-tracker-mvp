# 6-2 実証（PoC）の進め方

対象：候補A（中小部品メーカー）を想定。候補Bでも業務を差し替えれば同じ流れで使える。

## 概要

| 項目 | 内容 |
|---|---|
| 期間 | 8週間 |
| 費用 | 20万円（税別）。本導入時は導入費から全額差し引き |
| 対象業務 | 1業務に絞る：**過去の不具合・クレーム報告の類似事例検索＋是正処置書の下書き** |
| 利用者 | 品質保証部門の 3〜5名 |
| 機材 | **当社の検証機を貸し出し**（顧客の機材購入は本導入時） |
| 文書 | 過去3〜5年分の不具合報告・是正処置書（100〜500件程度）、作業標準書の一部 |
| 遠隔接続 | PoC期間中はなし（訪問で対応、顧客の情報管理審査を軽くするため） |

**仮決め：** PoCは当社検証機の貸出で行い、遠隔接続はしない。
- 理由：顧客の初期投資と社内審査のハードルを下げる。データは顧客社内から出ない。
- 別案：最初から顧客が機材を購入（本導入へそのまま移行できるが、PoCの敷居が上がる）。

## スケジュール

| 週 | やること | 成果物 |
|---|---|---|
| 0（事前） | NDA締結、PoC契約、情報管理担当者への説明 | NDA、PoC契約書、説明資料 |
| 1 | 業務の聞き取り（今どう探しているか、何分かかるか）、評価質問の作成（実際にあった質問20問と正解） | 現状の作業時間の記録、評価質問セット |
| 2 | 検証機の設置、文書の登録（権限は品質保証部門のみ）、AI利用ルール（PoC版）の説明 | 稼働環境、ルール1枚 |
| 3 | 操作説明（1時間）、試用開始、評価質問で初回採点 | 初回の精度点数 |
| 4〜6 | 現場で試用。週1回の訪問で困りごと対応・調整（文書の分け方、テンプレートの改善） | 週次メモ |
| 7 | 最終採点、利用者アンケート、作業時間の再計測 | 評価結果 |
| 8 | 報告会（社長・品質責任者）、本導入の提案（プラン・機材・費用・スケジュール） | PoC報告書、本導入見積 |

## 評価指標と合格ライン（仮）

| 指標 | 測り方 | 合格ライン |
|---|---|---|
| 類似事例を探す時間 | 開始前と第7週で同じ種類の調べ物を計測 | 50%以上短縮 |
| 回答の正しさ | 評価質問20問を顧客担当者が採点 | 16問以上（80%） |
| 根拠の確認しやすさ | 参照文書が正しく示された割合 | 90%以上 |
| 是正処置書の下書き | 作成時間と修正量 | 作成時間 30%以上短縮 |
| 使い続けたいか | 利用者アンケート（5段階） | 平均4以上 |
| 安全面 | 外部通信なし、権限外の文書が見えない | 違反ゼロ |

**仮決め：** 合格ラインは上表。
- 理由：中小の現場で「明らかに楽になった」と感じられる水準として設定［推定］。
- 別案：合格ラインを事前に顧客と決める（顧客の納得度は上がるが、初回打合せで時間がかかる）。→ 実際は**第1週に顧客と合意して確定**するのが望ましい。

## PoC後の分かれ道

| 結果 | 次の一手 |
|---|---|
| 合格 | スタンダードで本導入（機材発注 → 2〜4週間で移行、PoC環境の設定を引き継ぎ） |
| 一部合格（精度は不足、時間短縮は効果あり） | 対象文書の整理・テンプレート改善を2週間追加して再評価、またはライトで小さく開始 |
| 不合格 | 原因を報告（文書の質・量、モデルの能力、業務の向き不向き）。クラウドで済む業務の提案のみ行い終了 |

## PoCで当社が学ぶこと（事業側の検証）

- 導入作業の実工数（見積の30h／50hは妥当か）
- 中小製造業で効果が出る業務・出ない業務
- 精度点検の評価質問の作り方（他社に流用できる型）
- 価格への反応（月6万円は高いか安いか）
