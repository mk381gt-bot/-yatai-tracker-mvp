# 1-3 サービスの要件

設計（03-design）とタスク（07-tasks）は、この要件を満たすように組み立てる。

## 機能要件（顧客ができること）

| ID | 要件 | 優先 |
|---|---|---|
| F-01 | 社員がブラウザから社内AIとチャットできる（インストール不要） | 必須 |
| F-02 | 社内文書（PDF・Word・Excel）を登録し、内容を検索・要約・質問できる（RAG） | 必須 |
| F-03 | ユーザーごとにログインし、部署単位で見られる文書を分けられる | 必須 |
| F-04 | 機密レベルの低い業務だけ、クラウドAIを選んで使える（許可されたグループのみ） | 推奨 |
| F-05 | 定型業務のテンプレート（日報要約、報告書下書き、メール文案）をボタン一つで使える | 推奨 |
| F-06 | 回答に「参照した文書名」を表示する（根拠の確認ができる） | 必須 |
| F-07 | 回答の良し悪しを👍👎で送れる（精度点検の材料） | 推奨 |
| F-08 | 管理者が利用ログ（誰がいつ使ったか）を確認できる | 必須 |

## 非機能要件

| ID | 区分 | 要件 | 目標値（仮） |
|---|---|---|---|
| N-01 | 機密性 | 機密データ（L3、[01-architecture.md](../03-design/01-architecture.md)参照）は社外に送信しない | 送信ゼロ。ファイアウォールで外向き通信を限定 |
| N-02 | 機密性 | 遠隔点検は外向き接続のみ・多要素認証・顧客が停止できる | [06-remote-maintenance.md](../03-design/06-remote-maintenance.md) |
| N-03 | 完全性 | モデルは公式配布元から取得し、ハッシュ値を台帳管理 | 全モデル台帳登録 |
| N-04 | 可用性 | 営業時間内に使える。単一機材のため冗長化は標準では行わない | 稼働率目標 95%/月（SLO、保証ではない） |
| N-05 | 性能 | 同時利用者数に対し、待たされない速度 | 1人あたり 15トークン/秒以上、最初の文字まで5秒以内［推定・機材で変動］ |
| N-06 | 復旧 | 機材故障時、設定とデータを復元できる | 設定・索引の日次バックアップ、復旧目標 3営業日以内（メーカー保守依存） |
| N-07 | 保守性 | 他人（代替要員）が手順書だけで点検できる | 手順書・チェックリスト整備 |
| N-08 | 運用負荷 | 1社あたりの月間保守工数を抑える | ライト3h／スタンダード6h／プレミアム12h |
| N-09 | ライセンス | 使うソフト・モデルはすべて商用利用可 | 比較表で確認済みのもののみ |
| N-10 | 説明責任 | 点検結果を毎月記録し、顧客が取引先に提出できる | 月次点検報告書（A4 1〜2枚） |

## スコープ外（やらないこと）

- AIモデルの独自学習（ファインチューニング）は標準メニューに含めない（必要時は別見積）
- 基幹システム（生産管理・会計）の改修
- 24時間365日の監視・対応
- 社員個人のPC・スマホのサポート

**仮決め：** ファインチューニングは標準外。
- 理由：工数とGPU資源が大きく、RAG（文書検索）で中小の用途の大半は足りる［推定］。モデル更新のたびにやり直しになり保守負担が増える。
- 別案：プレミアムプランで年1回の軽量追加学習（LoRA）を含める。
